GCP Cloud Run — 公開手順

雅を Google Cloud で公開する

雅はサーバーレンダリング（Server Actions・データベース・Cookie認証）で動くため、 GCP では Cloud Run（コンテナ）＋ Cloud SQL for PostgreSQL で公開します。 静的ホスティングは使えません。これは 課金の有効な GCP プロジェクトが必要な、人間の作業で、 開発コンテナ内では実行できません。

準備するもの

着手前にそろえます。まず共通の変数を決めておくと楽です。

アカウント・権限

  • 課金が有効な GCP プロジェクト
  • Cloud Run 管理者 / Cloud SQL 管理者
  • Artifact Registry 管理者 / Cloud Build 編集者

ツール

  • gcloud CLI（認証済み）
  • （任意）Cloud SQL Auth Proxy
  • Node.js（マイグレーション実行用）

コード側

  • web/Dockerfile（用意済み）
  • provider = "postgresql" へ変更（手順3）
  • ADMIN パスワード等の秘密値
# 自分の値に置き換える共通変数
export PROJECT=your-gcp-project
export REGION=asia-northeast1          # 東京
export INSTANCE=miyabi-db
export DB=miyabi
export DBUSER=miyabi
export DBPASS='＜安全なパスワード＞'
gcloud config set project "$PROJECT"
1

API を有効化

使用するサービスの API をまとめて有効化します。

gcloud services enable \
  run.googleapis.com \
  sqladmin.googleapis.com \
  artifactregistry.googleapis.com \
  cloudbuild.googleapis.com \
  secretmanager.googleapis.com
2

Cloud SQL（PostgreSQL）を作成

インスタンス・データベース・ユーザーを作ります。

gcloud sql instances create "$INSTANCE" \
  --database-version=POSTGRES_16 \
  --tier=db-f1-micro \
  --region="$REGION"

gcloud sql databases create "$DB" --instance="$INSTANCE"
gcloud sql users create "$DBUSER" --instance="$INSTANCE" --password="$DBPASS"

# 接続名（PROJECT:REGION:INSTANCE）を控える
gcloud sql instances describe "$INSTANCE" --format='value(connectionName)'
3

Postgres 用にマイグレーション

既存の SQLite 用マイグレーションは作り直します。

重要 prisma/migrations の既存 SQL は SQLite 方言のため Postgres には適用できません。 provider を切り替えてベースラインを作り直します。
  1. prisma/schema.prisma の provider を変更
    datasource db {
  provider = "postgresql"
}
  2. Cloud SQL Auth Proxy を起動（別ターミナル）
    cloud-sql-proxy "$PROJECT:$REGION:$INSTANCE"   # 127.0.0.1:5432
  3. ベースライン作成＋（任意）シード
    export DATABASE_URL="postgresql://$DBUSER:$DBPASS@127.0.0.1:5432/$DB"
rm -rf prisma/migrations           # SQLite用履歴は退避 or 別管理
npx prisma migrate dev --name init # 初回のみ（以降は migrate deploy）
npm run db:seed                    # 任意：サンプル商品を投入
4

コンテナをビルドして push

Cloud Build で Dockerfile をビルドし Artifact Registry へ。

# リポジトリ作成（初回のみ）
gcloud artifacts repositories create miyabi \
  --repository-format=docker --location="$REGION"

# web/ ディレクトリで実行
cd web
gcloud builds submit \
  --tag "$REGION-docker.pkg.dev/$PROJECT/miyabi/web:latest"
5

Cloud Run にデプロイ

秘密値は Secret Manager 経由が安全です。

# シークレット登録（初回のみ）
printf '%s' "$DBPASS" | gcloud secrets create miyabi-db-pass --data-file=-
printf '%s' '＜管理画面パスワード＞' | gcloud secrets create miyabi-admin-pass --data-file=-

export CONN="$PROJECT:$REGION:$INSTANCE"

gcloud run deploy miyabi \
  --image "$REGION-docker.pkg.dev/$PROJECT/miyabi/web:latest" \
  --region "$REGION" \
  --allow-unauthenticated \
  --add-cloudsql-instances "$CONN" \
  --set-env-vars "NODE_ENV=production,ADMIN_USER=admin" \
  --set-env-vars "^@^DATABASE_URL=postgresql://$DBUSER@localhost/$DB?host=/cloudsql/$CONN" \
  --update-secrets "ADMIN_PASSWORD=miyabi-admin-pass:latest"
Cloud SQL 接続 --add-cloudsql-instances を付けると、コンテナ内の Unix ソケット /cloudsql/PROJECT:REGION:INSTANCE 経由で接続できます。上の DATABASE_URL はその形式です。 ^@^ は --set-env-vars の区切りを @ に変える指定（URL内カンマ対策）。

デプロイ完了後、表示される Service URL をブラウザで開いて動作確認します。

6

継続的な更新

以降の運用はシンプルです。

アプリの更新は「ビルド → デプロイ」を再実行するだけ

gcloud builds submit … → gcloud run deploy … でトラフィックが新リビジョンへ自動切替。

スキーマ変更時は、デプロイ前に prisma migrate deploy（Auth Proxy 経由 or Cloud Run ジョブ）を実行します。

Capacitor と連携 capacitor.config.ts の server.url にこの Cloud Run の URL を設定すれば、 iOS/Android アプリもそのままこの本番環境を表示します。

補足・チューニング

必要に応じて。

スケール
Cloud Run は既定でゼロスケール（無アクセス時は課金されにくい）。コールドスタートが気になれば --min-instances=1。
接続数
同時実行が増えると Cloud SQL の接続が増加。--max-instances / --concurrency や接続プーラーで調整。
リージョン
Cloud Run と Cloud SQL は同一リージョンにするとレイテンシ・コストで有利。
独自ドメイン
Cloud Run の「ドメインのマッピング」またはロードバランサで割り当て。
